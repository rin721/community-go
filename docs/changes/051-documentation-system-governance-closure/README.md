# 051 项目文档体系治理闭环

## 状态

已确认并实施。

## 目标

本变更不是只补 WebUI 启动示例，而是对当前项目文档体系做一次完整收口：

1. 让使用者从根 README 能找到当前项目边界、完整启动路径、首次使用方式、开发规范和运维入口。
2. 让每个当前业务模块、通用能力和前端子项目都有可达、准确且有唯一 authority 的说明。
3. 清理当前主题文档中的任务编号、过期阶段说明和历史实现语境，历史只留在 `docs/changes/`、`docs/research/` 或 ADR。
4. 建立“实现新技术、业务模块或功能时必须评估并更新相应文档”的机器可执行门禁。

## 明确边界

- `old-backend/` 按用户决定排除：不审计其内部文档，不修改其中内容，也不纳入链接、可达性或文档影响门禁。
- 根 Go 工程与 `webui/` 是当前构建和质量链的事实范围。
- `frontend/` 保留在审计范围内，但其是否接入当前后端必须以代码和交付链证据为准，不能因目录存在就宣称已集成。
- 本变更不删除、迁移或重命名 `frontend/`、`old-backend/`，不擅自完成仓库身份迁移，也不新增业务功能。
