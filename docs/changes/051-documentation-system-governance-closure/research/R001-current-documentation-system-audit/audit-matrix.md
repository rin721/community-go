# 当前文档体系审计矩阵

本矩阵只覆盖当前项目范围，`old-backend/` 明确排除。

| 领域 | 当前证据 | 结论 | 严重度 | 051 处理方向 |
|---|---|---|---|---|
| 根入口 | README 只给 Go 三条启动命令 | 未覆盖 WebUI 与首次使用的完整成功路径 | 高 | 重写为后端最小启动与全栈启动两条真实路径 |
| 项目边界 | 根文档未解释 root、`webui/`、`frontend/` 的状态 | 使用者无法区分当前集成、未集成与历史范围 | 高 | 新增仓库范围与当前状态 authority |
| 首次使用 | 无统一的 Setup、登录、Todo/API、management 验收指南 | 启动成功无法转化为可观察的产品验收 | 高 | 新增首次使用指南并从根入口直达 |
| WebUI 局部文档 | `webui/README.md` 缺失 | 子项目命令和模块边界不可局部发现 | 高 | 新增局部 README，并链接当前 WebUI authority |
| Auth 模块 | `internal/module/auth/README.md` 缺失 | 业务模块文档结构不完整 | 高 | 增加 Auth 局部说明并更新模块索引 |
| 模块索引 | Auth/Migration 没有完整可点击入口 | 局部文档不可达 | 中 | 四个当前模块全部链接并说明形态 |
| Capability 索引 | 17 个当前局部 README 从根 authority 不可达 | 实现有说明但体系找不到 | 高 | 完整链接 capability catalog/pkg index，并加回链 |
| API 使用 | `api/README.md` 偏生成器说明 | 缺少当前调用和验证入口 | 中 | 分开“怎么使用”和“怎么生成维护” |
| 配置 | 配置键有集中说明，但新增配置与文档无绑定门禁 | 后续容易漂移 | 高 | 将配置路径纳入文档影响映射 |
| 运维能力 | Cache/Storage/Observability/Execution/WebUI 交付缺少统一状态表 | 能力启用、资源和验证边界分散 | 高 | 增加运行能力矩阵和主题链接 |
| WebUI 交付 | CI 能构建 WebUI，但 Docker/release 不交付 dist | 文档不得暗示生产托管已完成 | 高 | 当前文档明确“本地开发已实现、生产交付未实现” |
| `frontend/` | README 指向不存在目录和脚本，CI/release 未覆盖 | 当前集成声明失真 | 高 | 改为事实状态页；集成/退役另立任务 |
| 当前与历史 | 当前主题文档含 032/035/036/042/043 等任务语境 | 当前 authority 被历史实现细节污染 | 高 | 当前文档改写为无任务前置的有效规则 |
| 变更历史 | 001–041 导入基线与 042+ 本仓库任务未分组 | 来源和证据强度不透明 | 中 | 在 change 导航标注基线导入边界 |
| 脚手架基线 | `.scaffold/identity.yaml` 要求的 baseline 文档缺失 | 明示契约断裂 | 高 | 补充只包含可验证事实的 baseline 文档 |
| 仓库身份 | remote 是 community-go，构建身份仍是 go-scaffold-template | 当前身份存在未决冲突 | 高 | 状态页如实标注；身份迁移另立任务 |
| 链接完整性 | 人工抽查未确认真实相对链接断裂，但无可靠解析器 | 无法持续保证 | 中 | 实现忽略代码块/行内代码的 Markdown 链接检查 |
| 文档可达性 | 当前 authority 图存在 17 个不可达局部 README | 文档存在但对使用者等同缺失 | 高 | 实现入口可达性门禁 |
| 新模块/能力 | 无 README/index 自动检查 | 新目录可静默落地 | 高 | 对 `internal/module/*` 与 `pkg/*` 做目录清单门禁 |
| 文档同步 | 无 docs impact 记录和 diff 检查 | 新技术/功能实现后可不更新文档 | 最高 | 引入机器映射、影响清单、跨平台脚本与 CI |

## 结论

问题的主因不是某一篇文档缺失，而是“当前 authority、历史证据、实现目录和质量门禁”没有形成闭环。051 必须同时完成当前内容修复和后续同步约束，否则只会再次产生同类缺口。
