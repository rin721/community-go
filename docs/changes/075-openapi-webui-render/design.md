# 075 设计：openapi 模块与 WebUI 契约渲染

支撑研究：R075-001（swagger-ui-react 选型与兼容风险）、R075-002（契约数据源与模块接入机制）。

## 总体数据流

```text
模块 binding/http Huma registrations            （唯一代码权威）
        │ go generate ./...（contract-gen）
        ▼
api/openapi.yaml  ├─> CI oasdiff 基线（既有）
        │ go run ./cmd/app webui generate（扩展后，同一命令）
        ▼
webui/src/generated/openapi-spec.ts  ──import──►  OpenAPIPage（模块内窄封装）
                                                      │
webui/src/generated/webui-registry.ts  ──manifest──►  /openapi 路由 + 菜单（既有机制）
```

- 三态数据源环境（server-hosted / separated / mock）都为“页面 import 同一生成文件”，零请求；mock 模式下页面数据天然一致，模块 `mock.ts` 提供空路由表（settings 先例）并注释说明。
- 契约物理权威仍是 `api/openapi.yaml`；`openapi-spec.ts` 是其 JSON 变换，随 `webui generate` 同命令同 `--check` 纪律，不会静默漂移。

## 生成器扩展（Go）

- 位置：`internal/composition/webui_spec.go`（新文件），提供：
  - `WriteWebUIOpenAPISpecFromCurrentDirectory(check bool) error`：读取 `.scaffold/layout.json` 的 `generatedArtifacts.openapi` 路径 → `go.yaml.in/yaml/v3` 解析为 `map[string]any` → `encoding/json` 序列化（键稳定排序，输出确定性）→ 渲染 TS 文件（头注释 `// Code generated by webui-gen; DO NOT EDIT.` + `export const webuiOpenAPISpecSourceRevision = "<api/openapi.yaml sha256>";` + `export const webuiOpenAPISpec = <json>;` 无 `as const` 宽类型，避免字面量类型爆炸）→ 写入 `webui.specOutput` 路径；`check` 模式做整文件严格比对（复用 registry 的 stale 语义与报错风格）。
  - 失败语义：`api/openapi.yaml` 缺失或解析失败 → 命令失败并输出原因（不做静默回退、不输出占位 spec）；`--check` 下内容不一致 → 非零退出。
- 命令装配：`cmd/app/main.go` 的 `webui generate` 分支在调用 `WriteWebUIRegistryFromCurrentDirectory` 后追加调用 spec 写入（同一 check 标志）。
- 布局清单：`.scaffold/layout.json` 的 `webui` 节新增 `specOutput: "webui/src/generated/openapi-spec.ts"`；同步 `internal/projectlayout/layout.go`（`WebUILayout.SpecOutput` + `isWithin roots.webui` 校验 + 路径映射输出）、两个 `webui_registry_test.go` fixture 字符串与 layout 测试。
- 不做：运行期读取/嵌入、对象进 catalog revision（spec 漂移由 --check 兜底）、第二份 YAML 产出。

## 新模块 `openapi`（WebUI-only，settings 同形态：无 module.go 业务层）

目录：

```text
internal/module/openapi/
├── README.md                    （局部包说明，指向权威文档）
└── binding/webui/
    ├── README.md                （模块 WebUI 说明，settings 先例）
    ├── binding.go               （webuicontract.Binding 声明）
    └── web/
        ├── OpenAPIPage.tsx
        ├── OpenAPIPage.test.tsx
        ├── openapi.module.css
        ├── mock.ts              （空路由表 + 注释）
        └── locale/en-US.json、locale/zh-CN.json
```

binding.go 要点：

- `ModuleID: "openapi"`；`Entries: [{ID: "openapi.docs", SourcePath: "OpenAPIPage.tsx"}]`；
- `Routes: [{ID: "openapi.docs", Path: "/openapi", EntryID: "openapi.docs", TitleMessageID: "webui.openapi.docs.title", Layout: RouteLayoutApp, DeliveryState: DeliveryImplemented}]`——**无 ViewOperationID**（与 settings 页一致的公开呈现；契约是公开仓库产物，不为文档页伪造 HTTP operation）；
- `Navigation: [{ID: "openapi.docs", RouteID: "openapi.docs", TitleMessageID: "webui.openapi.docs.title", IconID: "book", Order: 130}]`（顶级平铺；Order 取现有序列之后）；
- `Locales: en-US / zh-CN`，namespace `webui.openapi`；`MockSource: "mock.ts"`；
- `Requires: runtime / i18n / ui / mock`（无 http/query：页面零请求）。

页面设计（`OpenAPIPage.tsx`）：

- **与 WebUI 同等 UI 组件（用户要求）**：页面壳层与其余业务页面完全同源——`@webui/sdk/ui` 的 `PageHeader`（eyebrow/title/description）、`PageSection` 说明卡、`Skeleton` 加载占位、`InlineAlert` 错误呈现、`module-page` 平台类与模块 css module 根元素；不引入第二套页面骨架组件。只有 Swagger UI 的交互文档区（operation 列表/schema/请求面板）由 `swagger-ui-react` 渲染，属于该第三方库的固有呈现，不冒充平台组件。
- Swagger UI 占满内容区（容器自滚动，不与宿主滚动运行时冲突，默认 Lenis 行为）。
- 模块内窄封装 `OpenAPISpecView`（同文件或 `OpenAPISpecView.tsx`）：收敛 `SwaggerUI` props（`spec={webuiOpenAPISpec}`、`docExpansion="none"`、不启用 hash deep-linking（react-router SPA 冲突 + #10883 回归）、`tryItOutEnabled={false}` 默认关闭、`displayRequestDuration` 等取默认），`import "swagger-ui-react/swagger-ui.css"` 在模块内引入（随懒加载 chunk 加载）；导出 `webuiOpenAPISpec` 直接消费由生成器保障。
- 呈现说明（phase 2 不做但要在页面内注明语义）：Swagger UI 的 «Try it out» 针对 bearerAuth 可用 Authorize 注入 token（按操作自身契约）；`webuiSession`/CSRF 绑定操作无法从 Swagger UI 直接执行（服务端 fail-closed 不变）；mock 演示构建下无后端，请求类交互不可用——这些是既有安全边界的自然结果，页面内不做特别实现。
- 暗色主题：宿主 `<html>.dark` 下 swagger 默认亮色；模块 css 提供少量 `.swagger-ui` 变量覆盖（有限、可降级，失败不影响可用性）。

## 失败语义与降级

- 契约缺失/解析失败：`webui generate` 失败，不输出占位文件；既有构建链（托管前构建、generate:check 门禁）自然失败提示，杜绝“假成功”。
- Swagger UI 运行时异常（StrictMode 双挂载等）：风险已列入 R075-001；模块内 `OpenAPISpecView` 提供 mount 守卫降级（若实测需要），并保持页面壳（PageHeader/说明）不受影响。
- bundle 体积：swagger-ui-react 独立懒加载 chunk（Vite 动态 import 自动分块），首屏不受影响；实施时记录新 bundle 基线（对照 068 做法）。

## 验证方案

1. Go：`go test ./...`（新增/更新：webui spec 生成与 --check 测试、layout fixture、composition 菜单/registry 断言）、`go vet ./...`。
2. WebUI：`pnpm generate:check`、`pnpm typecheck`、`pnpm lint`、`pnpm lint:modules`、`pnpm test`（OpenAPIPage 测试：对 `swagger-ui-react` 做模块级 mock，断言 PageHeader 与 spec 容器；生成 spec 文件类型被 typecheck 覆盖）、`pnpm build`。
3. Playwright：dev project（认证态，manifest fixture 增补 openapi 路由/菜单）与 mock project（生成 manifest 自动含）各自断言 `.swagger-ui` 渲染 + 契约标题文本；截图留存。
4. 手动验收（模式 B）：启动 → `/openapi` 渲染、菜单导航、operation 展开、schema 查看；`VITE_WEBUI_DATA_SOURCE=mock` 演示构建（普通 `pnpm build` + `.env.local`，域名一致时浏览器同源）浏览验证。
5. 回归：既有 79+ vitest / 20+ Playwright 用例不回退；`pnpm e2e -- --workers=1` 全绿。
