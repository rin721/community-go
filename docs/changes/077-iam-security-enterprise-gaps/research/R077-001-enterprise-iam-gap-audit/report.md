# R077-001 研究报告：用户与权限体系企业级能力差距评估

## 1. 研究问题

当前「用户与权限体系」是否**完整、通用、闭环**，能力是否**成熟可面向企业级通用能力**？差距具体落在哪些能力面，哪些可以「边界内直接补」，哪些必须「重新研究/产品决策」后另行立项？

### 2.2 差距（按企业级能力面逐项核实）

| 能力面 | 当前状态 | 判定 |
| --- | --- | --- |
| 认证因素 | 仅密码 + Session；无 MFA/TOTP（`grep TOTP\|MFA\|otp` 无实现命中） | 候选（064 已列）；需选型研究 |
| 外部身份 | 无 OIDC/SSO/LDAP 登录；Auth 的 JWT verifier（JWKS）只支撑 token-scopes 凭据校验，不是用户身份源 | 需边界突破（054/058 列候选） |
| 口令策略 | 无历史口令（禁止复用）、无密码过期周期；最小/最大/复杂度已可配置（076） | 边界内可直接补 |
| 会话治理 | 无单账号并发会话上限、无设备指纹、无"踢出指定设备"粒度（只能摘要批量吊销） | 边界内可直接补 |
| 登录限流 | 账号级锁定已有；登录/setup 无 IP 维度限流（`http.rateLimit` 是全局入口 token bucket，不区分路径/来源） | 边界内可直接补（复用/对齐既有语义） |
| 授权语义 | 仅 allow；无角色继承、显式 deny、职责分离（SoD）、临时/带过期授权 | 需重新研究（058 触发条件：Casbin model 或 OpenFGA/OPA 对比） |
| 数据权限 | 无（组织关系不进授权决策，055/066 明确候选） | 需边界突破（数据范围四级 scope 需单独决策） |
| 多租户 | 无 domain | 需边界突破（058 明确候选） |
| 多实例一致性 | revision 协议 fail-closed 但未验证为分布式承诺（`security.md:31`）；跨实例授权变更依赖下次决策全量重读 | 需研究（既有 messaging 可承载失效广播） |
| 账户运营 | 无批量导入/导出、无邀请注册流程、无自助注册 | 需产品决策（静态清单边界内可补批量，邀请需外部通道） |
| 授权审计粒度 | 低敏审计无权限集合 before/after diff（065 明确非目标） | 需产品决策（与低敏字段域冲突） |
| 权限管理 | 权限键静态代码定义、无运行时管理/feature 映射 | 需产品决策（与 053 catalog authority 冲突） |

### 2.3 四维评估结论

1. **闭环**：核心闭环（账号↔角色↔权限↔会话↔授权↔审计）完整（058/064/065/066/076 已闭环）；企业闭环缺口集中在「认证因素（MFA）」「会话治理上限」「登录防爆破（IP）」与「多实例一致性」。
2. **完整性**：单应用、本地账号、静态策略场景完整；企业级要素（MFA、外部身份、口令历史/过期、会话上限、数据权限、多租户）多数缺失，但均已被既有记录为候选方向，无意外缺口。
3. **通用性**：模块边界、窄 facet、port/adapter、composition 装配、静态 Permission Catalog 机制是通用资产，可复制到新工程；但「能力随配置走」的通用化程度有限——多实例一致性、外部身份、多租户依赖需要跨模块重构。
4. **成熟度**：单实例生产可用（安全语义严谨、审计完备、契约成熟）；「企业级通用能力」仍需补齐认证因素与会话治理，并明确多实例与外部身份的承载方案。

## 3. 边界内可直接补（推荐下一批 077）

| 项 | 内容 | 理由 |
| --- | --- | --- |
| P1 口令策略增强 | 密码历史（禁止复用最近 N 次）、密码过期周期（maxPasswordAge）、复用 076 的 `passwordPolicy` 配置与 Service 冻结语义 | IAM 边界内、与既有密码校验路径同构、可验证 |
| P2 会话数量上限 | 单账号最大并发会话数（超出拒绝新会话或踢最旧），可配置；复用既有 `iam_sessions` 表与吊销语义 | IAM 边界内、闭环会话治理 |
| P3 登录 IP 限流 | login/setup 按来源 IP 的 token bucket（对齐 `http.rateLimit` 语义与 429/503 Problem），账号+IP 双维度 | transport/IAM 边界内、复用既有速率门禁模式 |

## 4. 需边界突破/重新研究（候选，另行立项，不进入 077 实施）

- **MFA/TOTP**（064 候选）：需技术选型（totp 库/QR/恢复码/绕过流程）研究后单独立项。
- **外部身份 OIDC/SSO/LDAP**（054/058 候选）：触发 Auth/IAM 身份来源重构，必须重新研究并确认。
- **授权语义增强（角色继承/deny/SoD）**（058 触发条件）：需重建 Casbin model 研究或 OpenFGA/OPA 对比，不叠加 matcher。
- **数据权限（组织数据范围）**（055/066 候选）：进入授权决策属重大边界突破，需单独确认范围与决策模型。
- **多租户 domain**（058 候选）：大工程，需产品决策。
- **多实例授权一致性**：可先用既有 `pkg/messaging` 设计失效广播研究，再决定承载路径。
- **批量导入/导出、邀请流程、授权审计 diff、运行时权限管理**：产品决策项，仅记录。

## 5. 适用 / 不适用场景

- 适用：单应用/单实例/本地账号/静态权限目录的脚手架与企业内网后台；需要完整闭环与强安全语义的管理面。
- 不适用：多租户 SaaS、外部身份主源（已有 OIDC/LDAP 的组织）、超大策略集、跨组织数据范围授权——这些场景需要 077 之后的分阶段重构/重新研究。

## 6. 局限

- 企业能力面清单基于公开 IAM 常见能力面与既有变更记录，不是外部咨询标准；未接入真实企业环境验证。
- 「成熟度」判定以工程门禁证据（测试/文档/契约）为准，未做渗透测试或容量压测。

## 7. 对本任务的影响

研究门禁结论：四维评估成立；推荐下一批 `077` 实施 **P1 口令策略增强 + P2 会话数量上限 + P3 登录 IP 限流**（全部 IAM/transport 边界内、可验证闭环）；MFA/OIDC/数据权限/多租户/授权语义增强等列为候选并给出触发条件，不进入本批实施。可进入计划阶段。
