# R077-002 研究报告：企业级能力可行性分析（MFA / API-Token / 风险控制 / 操作留痕 / 授权留痕 / 异常告警）

## 1. 研究问题

用户确认 077（P1 口令治理、P2 会话上限、P3 登录限流）后追加要求：分析当前项目**能否实现**以下六项企业级能力及其实现路径/依赖/工作量/立项建议：

1. MFA（多因素认证）
2. API-Token（机器访问令牌）
3. 动态风险控制（异常登录/设备/IP 风险）
4. 操作留痕
5. 授权留痕
6. 异常告警

## 2. 事实与可行性逐项分析

### 2.1 操作留痕 —— ✅ 已有基础，077 需联动

- **现状（已实现）**：065 业务操作审计——IAM/Organization/Navigation 写操作经 `OperationAuditWriter` 窄 port 写入 `auth_audit_events`（低敏：operation/action/resource_type/resource_id/outcome，subject 哈希）；`auth.audit.list` 只读查询带筛选分页。
- **差距**：无 before/after 权限集合 diff（065 明确非目标）、无归档/导出（产品决策）。
- **077 联动**：P1 历史写入、P2 会话踢除、P3 限流拒绝都属于「安全相关写/拒绝行为」，应按低敏审计面记录（写操作沿用 `auditOperation`；拒绝/限流按 `RecordAuthenticationFailure`/operation audit 的低基数类目），不新增第二套留痕。
- **结论**：可实现且已实现核心；本批只需保证新增行为落到既有审计面。

### 2.2 授权留痕 —— ✅ 已有基础，差距在产品决策

- **现状（已实现）**：Auth 认证/授权审计——每次 operation/action 判定（allowed/public/denied/missing_scope/rbac_denied/owner_mismatch）写低敏事件，含 revision 类别；审计查询支持按 operation/action/outcome/actorKind 筛选。
- **差距**：无「权限集合变更 diff」（角色权限替换的 added/removed 目前在 409 冲突响应可见，未入审计字段——065 设计为低敏不携带权限集合原文）。
- **结论**：可实现且已闭环；diff 进入审计需产品决策（与低敏字段域冲突时需拆分为「变更事件」单独字段）。

### 2.3 API-Token —— ⚠️ 边界内可新增，工作量中等，建议下一批

- **现状**：Auth 支持外部 JWT（JWKS 校验、token-scopes 直判）与 CLI/development principal；**无自管 API Token**（生成/吊销/轮换/scope 管理面不存在）。
- **实现路径（边界内新能力）**：
  - IAM 新增独立凭据类型 `iam_api_tokens`（hash 存储、scope 集合、created/expires/revoked_at，migration 00000x）；
  - Auth `CredentialVerifier` 增加 API Token 校验来源（复用 token-scopes Principal 语义：`NewPrincipal(subject, ActorService, scopes,...)`）；
  - HTTP 管理面 CRUD + 新权限键（如 `iam:api-token:*`）+ WebUI 页面 + 审计。
- **依赖/重构**：无外部依赖；需要新增权限键（与「不新增权限键」惯例不一致，但新能力授权域属正常扩展，需求阶段明确即可）；token 创建时返回明文一次，此后仅存 hash。
- **工作量**：M（表+repo+service+auth verifier+HTTP+WebUI+测试）。
- **建议**：下一批独立变更（078）——可形成完整闭环（发证→使用→吊销→轮换→审计），与本批 P1-P3 无耦合。

### 2.4 MFA/TOTP —— ⚠️ 可实现，需先技术选型，工作量中高，候选

- **现状**：无任何二因素（grep TOTP/MFA/otp 无实现）。
- **实现路径**：
  - TOTP（RFC 6238）secret 生成/绑定（扫码 QR）/校验；登录第二步验证；会话标记 MFA 状态（补充 Principal/受限语义或新状态位）；恢复码（一次性）；失败计数与告警联动；审计。
  - IAM 新表（`iam_totp_secrets`/恢复码）+ 绑定/校验 service + HTTP（绑定/校验/解绑）+ WebUI 安全页 + 配置（是否强制、重试次数）。
- **技术选型（AGENTS 3.2 先例）**：候选库 `github.com/pquerna/otp`（Apache-2.0、成熟、持续维护）或自研（标准库 hmac+time 可实现校验，但 secret 生成/救援码/重同步边界自行处理风险更高）。选型需在立项研究档案完成后再决定。
- **依赖/重构**：QR 呈现需前端库（qrcode 类）或后端生成图像（图像库）；与动态风险控制可联动（高风险→强制 MFA）。不依赖外部服务。
- **工作量**：M+（表/migration/绑定/校验/恢复/UI/测试）。
- **建议**：候选（064 已列）；需先做选型研究（同 058 模式：研究→计划→确认），单独立项，不混入 077。

### 2.5 动态风险控制 —— ❌ 当前不可直接实现，需专门设计与外源决策

- **现状**：无设备指纹、无 IP 地理/信誉、无登录行为基线（`grep risk/geo/fingerprint` 无实现）。
- **可行的最小路径**：
  - 因子采集：浏览器设备指纹（localStorage 随机 ID + UA/屏幕特征，弱指纹）、登录 IP（来自 trustedProxyCIDRs 后的 RemoteAddr）、登录频率；
  - 简化规则引擎：新设备+短时间异地 + 成功率等 → 风险档位；
  - 风险动作：要求 MFA / 拒绝登录 / 触发告警（需 MFA 与告警先落地）；
  - IP 地理/信誉：离线 GeoLite2（MaxMind，许可注意）或外部服务（可观测性边界），或首版只用「IP 段不在历史登录段」的简化判定。
- **依赖/重构**：会话/凭据流新增环境因子存储；规则引擎属于新业务组件；误报与可用性需要产品决策（企业级成熟要求显式规则集与干跑阶段）。
- **工作量**：H；**建议**：候选大项——先独立设计研究（规则集、因子、数据源、与 MFA/告警的联动），不做简化版本进 077（避免半成品规则造成误拒）。

### 2.6 异常告警 —— ⚠️ 边界内可新增，工作量中，候选/下一批

- **现状**：无任何通知通道（grep webhook/notify/alert 无业务实现）；审计事件已低敏落库。
- **实现路径**：
  - 项目自有窄 port（如 `AlertSink`）+ 首期 webhook provider（受控配置 URL/签名/频率合并）+ 规则集（连续失败、账号锁定、异地/新设备登录、权限变更、MFA 失败、限流拒绝）；
  - 基于既有审计事件流（auth_audit_events）实现「审计→规则→通知」联动，不新建事件系统；可复用 `pkg/messaging` 作为异步通道（跨模块解耦）。
- **依赖/重构**：新窄 port + provider + 规则配置；与多实例边界一致（webhook 调用方跨实例无状态）。
- **工作量**：M；**建议**：候选（边界内可落地），与 MFA/风险控制联动后价值最大；首期最小版（连续失败+锁定+权限变更 3 条规则 + webhook）可并入后续变更立项（078/079），不混入 077。

## 3. 结论矩阵

| 能力 | 当前状态 | 可实现性 | 建议 |
| --- | --- | --- | --- |
| 操作留痕 | ✅ 已实现（065） | 高 | 077 起新增行为纳入既有审计面 |
| 授权留痕 | ✅ 已实现（Auth 审计） | 高 | 权限集合 diff 进入审计需产品决策 |
| API-Token | ❌ 缺失 | 中高（边界内新能力） | 下一批独立立项（需新增 `iam:api-token:*` 权限键） |
| MFA/TOTP | ❌ 缺失 | 中高（需选型） | 候选：先完成技术选型研究再立项 |
| 动态风险控制 | ❌ 缺失 | 中（需外源/设计） | 候选大项：独立设计研究 + 与 MFA/告警联动 |
| 异常告警 | ❌ 缺失 | 中（边界内） | 候选：最小规则+webhook 可后续立项 |

## 4. 适用 / 不适用

- 适用：在既有单实例、本地账号、静态权限目录骨架内评估扩展；每个能力都能落到既有模块/port/facet 边界。
- 不适用：把六项全部塞入 077（MFA/风险控制/API-Token/告警均含独立决策点）；把半成品风险规则做成默认开启；在未完成选型时引入 TOTP/QR 依赖。

## 5. 对本任务的影响

- 077（P1-P3）保持已确认范围；新增要求：P1-P3 的新增行为（口令历史写入、会话踢除、登录限流拒绝）接入既有低敏审计面（操作留痕/授权留痕联动）。
- API-Token、异常告警列为 077 之后的候选批次；MFA、动态风险控制需先完成选型/设计研究；六项结论写入 077 变更记录与候选清单，不作为本批验收项。
