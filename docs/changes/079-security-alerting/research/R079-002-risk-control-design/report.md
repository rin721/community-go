# R079-002 研究报告：动态风险控制设计

## 1. 研究问题

动态风险控制（异常登录/设备/IP 风险）在既有体系上应如何设计：因子、数据源、风险规则与动作、与 MFA/告警的联动，以及首版边界（R077-002 判定需先设计研究）。

## 2. 事实与现有能力

- 已有：账号级锁定（MaxFailedAttempts）、登录 IP 限流（`http.rateLimit.routes`，077）、MFA/TOTP（078，登录两步 + challenge）、安全告警（R079-001，本批新增 Webhook 通道）、低敏审计（065）。
- 缺失：会话不记录来源 IP；无设备指纹；无 IP 地理/信誉数据源；无风险规则引擎。

## 3. 设计轮廓

### 3.1 因子采集（前置依赖）

- **来源 IP**：`trustedProxyCIDRs` 解析后（既有 `pkg/httpx` trusted proxy 中间件）在认证边界记录到会话（`last_login_ip`）或审计（低敏字段——需 065 字段域扩展决策）；
- **设备指纹（弱指纹）**：浏览器侧生成随机设备 ID（localStorage，类 072 本地偏好），随 CSRF/会话头携带；服务端存会话设备摘要（哈希）——不采集指纹画像隐私；
- **登录地理（可选）**：离线 GeoLite2（MaxMind，需许可评估）或 IP 段内简化（历史登录段外=异地）——数据源决策。

### 3.2 风险规则（建议简化，避免误拒）

| 规则 | 输入 | 动作（可配置档位） |
| --- | --- | --- |
| 新设备 + 短时间异地 | 设备摘要 + IP 段 | 要求 MFA（联动 078）/ 拒绝 / 仅告警（联动 079） |
| 高频失败 + 异常时段 | 失败计数窗口 | 告警 / 临时拒绝 |
| 风险档位 | 评分（因子加权，首版保守阈值） | 三档：通过 / 提示 MFA / 拒绝 |

### 3.3 与既有能力联动

- 不改变授权权威：风险只影响「认证强度」（要求 MFA 或拒绝）；
- 告警通道复用 R079-001 webhook（高风险事件告警）；
- 需要「干跑模式」（只告警不阻断）先行观察误报，再灰度到要求 MFA/拒绝。

### 3.4 边界与风险

- 弱设备指纹可被规避（不构成强认证）；IP 地理依赖外部数据（许可/准确性）；
- 误拒直接损害可用性 → 规则默认全关、干跑优先；
- 属于跨登录/会话的数据采集与规则组件：需独立立项（设计评审 + 产品确认），本批不实施。

## 4. 结论

动态风险控制可基于 077/078/079 的既有能力（IP 限流、MFA、告警）分阶段落地，但前置依赖（IP/设备采集与数据源决策）与误拒风险需要**独立设计立项**：先补「登录来源 IP 与环境摘要」的最小采集（作为认证审计/会话字段），再引入干跑规则。本批（079）只完成设计研究归档与最小采集的前置评估，不实施风险规则。
