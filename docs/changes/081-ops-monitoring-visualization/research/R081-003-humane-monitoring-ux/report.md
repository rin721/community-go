# R081-003 研究：监控可视化的人因形态（面向用户的服务器状态展示）

## 1. 研究问题

081 首版监控分区（文本卡 + 迷你折线）被判定"迷惑、不像给人看的"。本档案研究主流监控产品（Grafana、Datadog、Netdata、1Panel/宝塔、status 页类如 statuspage.io/Uptime Kuma）如何向用户呈现服务器与服务状态，输出本项目可落地的组件形态。

## 2. 复核限制

web 检索通道本次不可用（api key 失效，与 076 起一致）；以下形态依据为公开产品惯例与本站点自研 UI 原语能力，证据性质为"惯例对照 + 代码可实现性"，非官方文档逐条复核。实施后以真实渲染与交互验收代替。

## 3. 主流形态对照（事实）

| 产品 | 服务器/服务状态的呈现方式 | 人因要点 |
| --- | --- | --- |
| Grafana | Stat 面板（大数值 + 阈值着色 + 迷你趋势）+ Time series（坐标轴/图例/时间范围）；Dashboard 网格 | 一眼扫大数字；趋势图带轴与图例；阈值映射红黄绿 |
| Datadog | 时序图 + host/服务状态列表；monitor 状态（绿=正常、黄=警告、红=故障）全局横幅 | 全局健康横幅 + 逐项状态灯 |
| Netdata | 每指标一张实时卡：大数字 + 迷你实时曲线 + 状态徽标（正常/警告/损坏） | 卡式指标 + 实时感（"5 秒前"类时间戳） |
| 1Panel/宝塔 | 服务器概览卡（CPU/内存/磁盘）：大数字 + 百分比进度条 + 折线图 | 数值+占比+趋势三件套；磁盘/内存用进度语义 |
| status 页（statuspage.io/Uptime Kuma） | 组件列表：名称 + 状态圆点（operational/degraded/major outage）+ 附加说明；总横幅"所有系统正常" | 行式组件状态 + 语义词 + 颜色；人类可读状态词而非枚举值 |

## 4. 共性结论（本项目应做到的"给用户看"要素）

1. **语义状态而非原始枚举**：绿=正常 / 黄=降级 / 红=不可用，配人类可读词（Operational/Degraded/Unavailable），不显示 `running`/`ready` 等内部枚举裸值。
2. **全局健康横幅**：首屏第一眼是"全部正常 / N 项降级 / N 项故障"，而非堆积字段。
3. **大数值指标卡**：一屏可扫（内存、请求速率、goroutine、进程 CPU），大数字 + 单位 + 迷你趋势 + 状态色；优先于"小标签+小数字"网格。
4. **带坐标轴的时间序列图**：y 值刻度 + x 时间标签 + 图例，替代无轴折线。
5. **组件状态行式列表**：名称 + 状态圆点 + 状态词 + 关键附加（重启次数/最近活动/关于本组件的一句说明），异常行高亮。
6. **实时感**：显示"最近采样 5 秒前"并持续刷新，让用户确信是活数据。

## 5. 对 081 的影响（重设计方案）

监控分区重构为四块（自研原语，无新依赖）：
- **健康横幅**：复用 CapabilityBanner——"全部系统运行正常"或"N 项降级 / N 项故障"（计数来自 units 状态语义映射）。
- **指标卡行**（StatGrid 升级）：内存（GiB、含趋势 sparkline）、请求速率（/s、趋势）、Goroutine（趋势）、进程 CPU%（由 process_cpu_seconds_total 差分，趋势）；卡大数值 + 单位 + 趋势 + 状态色。
- **时序图**：chaart 原语增加坐标轴版（y 刻度 + x 时间标签 + 网格 + 图例，可从既有 LineChart 演化出 AxisLineChart）。
- **组件状态表**：行式列表（名称 + 状态圆点与状态词 + 一句话说明），degraded/failed 行高亮；给出 uptime 与最近采样时间。
- 移除首版"纯文本健康列表/Surface 堆叠"的呈现方式。

## 6. 适用 / 不适用

- 适用：单进程自托管监控页的"人看"形态；与既有自研 UI 原语（StatusPill/CapabilityBanner/StatCard）一致并可复用。
- 不适用：复杂 BI/图标库级交互（仍候选）；多实例拓扑视图（候选）。
