# 084 需求：逐页推翻低质量布局并补全可推导业务闭环

## 产品目标

- 每个页面：第一次接触的用户无需猜测即可理解信息层级、输入区域、可操作项、状态和下一步动作；视觉密度、控件辨识度、功能完整度、交互效率、组件复用、整体一致性达到成熟商业 Admin 水平。
- 禁止仅改颜色/圆角/padding/宽高或旧骨架上美化；凡出现「控件无意义铺满、输入框巨大或不可识别、留白失控、字段逐行堆砌、信息层级弱、页面空散、组件比例失衡、操作入口不明确、复杂业务用基础组件拼凑」即推翻布局重新组织。
- 现有前后端只作为理解业务实体/数据/流程/技术约束的证据，不作为产品边界；可补全「从现有业务可合理推导」的产品能力（含后端 API 扩展），无法推断的规则标记待确认。

## 范围（第一批，本变更实施）

| 页面 | 目标 |
| --- | --- |
| Departments | 目录工作台：搜索树 + 详情/编辑/创建一体化右侧面板；重命名与换父级（后端 PATCH 已支持）；归档/恢复带确认；创建从顶部横幅移入面板，消除左密右空 |
| Positions | 岗位名录工作台：紧凑 DataTable（编码/名称/状态/创建时间）+ 行菜单（重命名、归档/恢复确认）；创建为受控对话框；删除 card-grid 稀疏行 |
| Assignments | 账号组织分配：左「账号列表 + 搜索」右「分配编辑器（部门 + 岗位复选组）」，两栏 master-detail，消除全宽堆叠 |
| Menus | 修复 P0 截断：右侧面板改为可滚动自适应用户详情区，策略控件纵向分组；所有菜单标题跨 namespace 翻译（translateMessage）；空态 |
| OpenAPI | 首访默认选中第一个接口；无选中时显示可操作空态（打开第一个/搜索），列表滚动边界可辨 |
| Permissions | 修复描述「翻译资源缺失」；表格密度与列宽收敛 |

## 非目标（记录待后续批次/待确认）

- Settings 开关行、密码表单 confirm 字段、ApiTokens 创建分组、Login/Setup 重构 → 084 后续轮次。
- 「账号批量操作」「会话按账号过滤」「审计按账号过滤」＝可推导能力，但涉及后端 list 契约扩展 → 待 084 后续轮次按 DEC 评估。
- MFA 之外的认证因素、组织数据权限、动态菜单 → 明确不在本变更（既有 authority 记录为候选）。

## 验收标准

1. 上述 6 个页面通过 codex 多模态复查：无 P0/P1 结构性问题；密度/分组/层级达标。
2. 新增交互（编辑、重命名、默认选中、空态动作）在 mock e2e 或 vitest 有断言，lint/typecheck/vitest/build 全绿。
3. 翻译键 zh/en 成对、无「翻译资源缺失」直出；Menus 不再显示原始 i18n key。
4. 不删除任何既有有效业务能力（创建/归档/恢复/分配/启停等全部保留）。
