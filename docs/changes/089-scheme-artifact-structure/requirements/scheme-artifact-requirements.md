# 方案产物需求

## 目标与使用场景

当客户或产品负责人提出一个新方案时，产物必须同时支持三种阅读目的：

- 客户判断业务目标、范围和验收结果；
- 技术人员理解可实施的详细方案；
- 项目成员查看哪些工作已完成、哪些仍未完成。

## 需求

- `REQ-089-001`：每个新方案必须同时存在需求、设计和任务三类产物，不能用研究报告、聊天回复或单一综合文档代替。
- `REQ-089-002`：需求必须面向客户与产品使用方，说明目标、使用场景、范围、约束、非目标和可验收行为。
- `REQ-089-003`：需求必须使用目录承载，提供清晰入口，并允许按业务主题继续拆分，不能把大量内容集中到一个文件。
- `REQ-089-004`：设计必须面向技术人员，给出足以实施和验证的详细设计，而不是只有方向概述、文件列表或任务名称。
- `REQ-089-005`：设计必须使用目录承载，提供清晰入口，并按技术主题拆分详细内容。
- `REQ-089-006`：任务必须是可勾选的完成清单，明确区分未完成 `[ ]` 和已完成 `[x]`；只有达到完成条件并记录证据后才能勾选。
- `REQ-089-007`：历史方案不因本规则强制批量迁移；后续实质性新方案使用新序号和新结构。

## 非目标

- 不要求客户阅读内部接口、包路径、状态机或测试实现。
- 不强制所有方案使用完全相同的需求章节或技术设计分篇。
- 不修改历史方案内容，也不在本任务中新增自动校验脚本。

## 验收标准

- 根规则明确三类必备产物及各自受众。
- 新方案固定使用 `requirements/`、`design/` 和 `tasks.md`。
- `requirements/README.md` 与 `design/README.md` 只做摘要和导航，且各自至少包含一份语义明确的实质性分篇。
- `tasks.md` 的任务状态全部用 Markdown checkbox 表示。
- 089 自身按新规则形成完整示例。
