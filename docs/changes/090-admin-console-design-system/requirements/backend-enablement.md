# 后端支撑能力需求

## 1. 目的

正式后台控制台不能依赖浏览器拼接多个不一致快照，也不能因现有接口较少而把详情和运营页面降级成字段展示。后端应提供与管理任务匹配的查询投影、影响预览、稳定结果和审计信息。

## 2. 正式产品基线（P0）

### BE-090-001 一致查询

主要资源列表使用一致的查询、排序、分页/游标、总量和可选 facet 语义。非法排序、过大页面和不支持的过滤必须返回可识别错误，不能静默忽略。

### BE-090-002 核心详情投影

账户、角色和其他核心实体提供面向详情页的聚合读取，包含版本、生命周期、关键关系、最近活动摘要和允许的操作。字段缺失与空值语义必须明确。

### BE-090-003 影响预览

权限变更、组织移动、批量停用/归档、会话吊销和 Token 撤销等高影响命令，在需要时提供一致快照下的影响预览及版本/过期约束。

### BE-090-004 稳定批处理结果

批处理返回已处理、成功、失败和逐项错误，支持幂等与安全重试；错误使用稳定代码并保留可诊断原因，不泄露敏感数据。

### BE-090-005 可调查审计

审计事件具有稳定 ID、关联 ID、时间范围查询、确定排序与安全详情投影；保留策略和可查询时间范围可被 UI 告知用户。

### BE-090-006 偏好同步

需要跨设备保持的语言、时区、主题、密度与通知偏好由服务端持久化，并定义缺失、默认、组织策略覆盖和用户修改的优先级。

## 3. 效率增强（P1）

- 关系反查和数量摘要，避免列表/详情产生 N+1 请求。
- Token 使用、会话、组织成员、导航变更和运维健康的受控业务投影。
- 统计接口明确指标口径、时间范围、时区、数据延迟和权限。
- 大规模导出和批处理进入可查询进度的异步任务。

## 4. 规模化能力（P2）

- 保存/共享视图、异步报告和通知行动中心。
- 在真实容量与运营需求成立后提供趋势、容量预测和异常聚合。

## 5. 安全与隐私约束

- 不向 UI 返回凭据、完整 Token、Cookie、原始请求体、完整 DSN 或未审查的错误文本。
- 设备、网络和审计上下文采用最小必要字段，并服从保留和访问策略。
- 一次性密钥只在创建或轮换结果中短暂提供，之后不可再次读取。
- 导出、批量和详情读取继续经过现有权限模型；前端隐藏按钮不能替代服务端授权。

## 6. 验收

每个新增契约必须有明确领域所有者、错误语义、权限、分页/容量边界、审计行为和测试证据。UI 迁移不得用假聚合或静态数据掩盖尚未实现的 P0 契约。
