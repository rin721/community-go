# 控制台整体体验需求

## 1. 用户目标

管理员进入任一页面后，应在几秒内理解“我在哪里、当前状态如何、最重要的操作是什么”，而不需要先辨认多层导航和重复标题。

## 2. 全局骨架

### UX-090-001 单一位置表达（P0）

- 当前页面只能有一个明确选中的导航叶节点。
- 页面只出现一个主标题；面包屑、页签和章节标题不得重复同一信息。
- 工作区栏只在确有多个可切换上下文时显示；单一固定工具不占用一整层导航。

### UX-090-002 内容优先（P0）

- 常见 1280px 桌面视口中，主内容应保持足够宽度，不能被全局与局部导航合计挤压成窄栏。
- 列表页首屏应能同时看见标题、主要操作、查询工具和数据起始区域。
- 页面间的最大宽度、边距和滚动行为保持一致；复杂工作台可使用明确的全宽模式。

### UX-090-003 工具优先级（P0）

- 顶部区域优先展示当前位置、全局搜索、环境/健康提示、通知和账户入口。
- 主题、语言、密度等低频设置进入统一偏好入口，不在每页持续争夺空间。
- 窄屏只保留核心动作，其余工具进入有标签的菜单。

## 3. 视觉语言

### UX-090-004 克制且语义化的色彩（P0）

- 一个品牌强调色用于焦点、选中和主要动作。
- 成功、警告、危险、信息和中性状态使用稳定语义色；普通模块不得以彩虹色区分。
- 亮色与暗色主题都满足文本、控件和焦点可辨识要求。

### UX-090-005 稳定层级（P0）

- 标题、正文、辅助信息、标签和数字形成有限且一致的字号/字重层级。
- Card 只用于确有分组、边界或独立状态的内容，不作为所有章节的默认背景。
- 阴影主要用于浮层和需要脱离文档流的表面；普通内容优先用间距和分隔线组织。

### UX-090-006 密度可预测（P0）

- 控件、表格行和页面留白采用少量预定义密度，不允许页面任意创造尺寸。
- 默认密度适合持续管理工作；数据密集用户可切换紧凑密度并保存偏好。
- 触摸设备自动满足最小可操作面积，不机械套用桌面紧凑高度。

## 4. 响应式与可访问性

### UX-090-007 结构性响应（P0）

- 桌面、平板和手机的导航、工具条、详情和工作台有明确结构转换规则。
- 双栏工作台在手机上变为分段页面或可切换面板，不允许横向裁切核心内容。
- 表格在窄屏按列优先级隐藏、汇总或转为记录列表；不得仅缩小字体。

### UX-090-008 键盘与辅助技术（P0）

- 核心流程支持键盘完成，焦点顺序与视觉顺序一致，焦点样式始终可见。
- 弹窗、抽屉、菜单、树和数据网格具有正确的焦点管理与状态公告。
- 状态不能只靠颜色表达；图标、文字或可访问名称必须补充语义。

## 5. 完整状态

### UX-090-009 状态矩阵（P0）

每个读取页面必须区分：初次加载、后台刷新、正常有数据、尚无数据、筛选无匹配、无权限、离线/网络失败和服务异常。每个写操作必须区分：待确认、进行中、成功、字段错误、冲突、部分失败和完全失败。

### UX-090-010 可恢复反馈（P0）

- 错误说明发生了什么、影响范围和可执行的下一步。
- 后台刷新不得清空已有内容或使页面跳动。
- 空状态提供与权限相符的首个行动；无匹配状态提供清除筛选。
- 成功反馈短暂但可追溯，重要批处理结果可再次打开。

## 6. 非目标

- 不追求为了“现代感”增加动画、渐变、玻璃效果或大面积装饰。
- 不复制参考图的品牌、字段和页面。
- 不为了视觉统一牺牲专业后台所需的信息密度和可访问性。
