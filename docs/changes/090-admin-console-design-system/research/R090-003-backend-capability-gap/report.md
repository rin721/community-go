# 成熟后台控制台的后端能力缺口

## 1. 当前能力基线

当前 WebUI registry 与模块 API 覆盖认证、IAM、导航、组织、Todo 与基础运维。已有能力不是空白：

- 账户支持查询、状态/归档过滤、角色过滤、排序、创建、更新、密码、角色、批量状态和批量归档；
- 角色支持列表、创建、更新、归档和权限分配；
- 权限支持列表及反查角色；
- 会话支持过滤、排序和批量吊销；
- API Token 支持创建、更新、启停、撤销和轮换；
- 组织部门/岗位支持树、增改、启停、归档和移动，账户组织任职支持读取与替换；
- 审计支持按操作、动作、结果、操作者类型和资源类型过滤；
- 运维支持构建、启动、存活、就绪、诊断与 Prometheus 文本指标。

这些能力足以支撑第一阶段统一列表模式和部分编辑流程，但不足以支撑成熟的详情、关系、趋势和运营决策界面。

## 2. 缺口不是“多几个按钮”，而是业务投影不足

后台 UI 需要把资源的状态、关系、影响和变化过程表达出来。仅有 CRUD 操作时，前端只能展示字段和操作按钮，无法回答：

- 这个对象现在是否健康、为何如此、最近发生了什么？
- 修改它会影响哪些账户、权限、会话或组织节点？
- 批量任务执行到哪里，哪些失败，是否可重试？
- 列表中的异常是个例还是趋势？
- 审计事件之间如何按请求、操作者和资源串联？

因此应补充面向 UI 任务的只读投影和命令结果，而不是让浏览器跨多个接口拼装不一致快照。

## 3. 分级能力建议

### P0：支撑首轮正式产品迁移

| 领域 | 当前缺口 | 建议契约方向 | UI 收益 |
| --- | --- | --- | --- |
| 通用列表 | 部分资源分页/排序/过滤不一致 | 统一 query、sort、page/cursor、total/facets 语义 | 统一筛选、分页和 URL 状态 |
| 账户 | 缺少完整详情与活动摘要 | 账户详情投影：生命周期、角色、组织、会话摘要、最近活动、版本 | 正式详情页，不再只是字段 Drawer |
| 角色/权限 | 缺少影响范围与风险信息 | 角色详情、成员数量、权限分类/风险、变更影响预览 | 权限配置可理解、可确认 |
| 审计 | 缺稳定事件标识、时间范围与详情 | eventId、correlationId、时间范围、稳定排序、allowlist 详情 | 可追踪、可分享、可调查 |
| 批量操作 | 同步结果语义不完全统一 | processed/failed/errors、幂等键、逐项稳定错误码 | 部分失败可以明确呈现和重试 |
| 用户偏好 | 多项设置仅在浏览器本地 | locale、timezone、theme/density、通知偏好的服务端模型 | 跨设备一致且可审计 |

### P1：提升管理效率和运营可见性

| 领域 | 建议能力 |
| --- | --- |
| 会话 | 当前会话标记、认证方式、受控客户端标签、吊销原因；网络/设备信息须采用隐私最小化投影 |
| API Token | owner/scopes、最近使用摘要、过期与轮换历史；密钥仍只在创建/轮换时一次性返回 |
| 组织 | 节点成员/子孙数量、反向成员查询、分页任职目录、批量任职、安全移动预检 |
| 导航 | schema 校验、预览/diff、事务性排序、默认值恢复、版本与变更历史 |
| 审计 | 聚合 facets、导出任务、保留策略说明和资源时间线投影 |
| 运维 | typed health overview、时间序列、近期异常/事件、能力健康；不要求产品 UI 自行解析 Prometheus 文本 |

### P2：规模化与复杂运营

- 统一异步 Job：状态、进度、部分结果、取消、过期、下载和重试；用于大规模导出、批处理和报表。
- 通知/行动中心：面向当前操作者的失败任务、风险提醒和待处理动作。
- 保存视图和共享筛选：服务端持久化列、排序、过滤与权限边界。
- 统计时间序列和容量趋势：在真实运营需求与指标口径确认后提供，不提前构造无用途报表。

## 4. 契约原则

- 列表投影、详情投影和命令模型可以不同，避免用一个巨型 DTO 同时服务所有场景。
- 统计口径、时间窗口、时区、采样/延迟必须在契约中明确。
- 批量命令必须保留逐项结果和稳定错误类型，不得只返回总成功布尔值。
- 审计详情采用字段 allowlist；禁止把原始请求、Token、Cookie、完整 URL/query 或敏感配置直接返回 UI。
- 关系和影响预览应由服务端在一致快照中计算，避免前端 N+1 查询后自行推断。
- 长任务采用异步 Job，不用超长 HTTP 请求和无限轮询冒充进度。

## 5. 非目标与未知项

- 不因为“成熟控制台通常有报表”就预设所有报表；每个统计接口需先定义业务决策和口径。
- 不把 IP、User-Agent 或设备指纹原样展示作为成熟度标志，隐私与安全边界优先。
- 本研究没有授权创建数据库字段、migration 或接口；具体模型仍需在实施子任务中依据现有领域契约设计并验证。

## 6. 对实施顺序的影响

UI Shell、Token 和可由现有接口支撑的列表模式可以先实施；依赖 P0 投影的详情、审计和影响预览不得用前端假拼装完成。页面迁移清单必须为每一页标记“现有后端可完成”“需要 P0 契约”或“推迟至 P1/P2”。
