# 上下文化组件体验需求

## 1. 客户目标

作为后台管理用户，我希望同一页面内的控件层级清楚、布局稳定、状态一致；简单任务使用
轻量控件，复杂表单保留完整提示；列表、工作台和设置页面不因共享组件而层层套框，也不
因某个全局组件调整而在无关页面产生视觉回归。

## 2. 可验收行为

- REQ-093-001：同一交互能力只能有一个行为来源，但 form、filter、toolbar、inline、
  table、dialog、workbench 可以有受控且可解释的形态差异。
- REQ-093-002：任一可见区域只能有一个主要 Surface owner；Card、Table、Pagination、
  FilterBar、EmptyState 或业务 Pane 不得形成无意义的重复边框、圆角、背景和阴影。
- REQ-093-003：字段标签、帮助、错误和必填语义只出现一次；紧凑筛选不得呈现完整表单
  字段外壳，完整表单不得丢失 Label/Error/Description。
- REQ-093-004：主要动作、次要动作、行内动作、图标动作、选择态动作和危险动作必须按
  任务层级呈现，不能都继承同一尺寸和强调度。
- REQ-093-005：少量互斥选项、页尺寸、筛选条件、语言、主题和工作台导航必须按选项规模、
  操作频率和空间选择合适控件，不因“统一来源”强制使用重型 Select 或 Card。
- REQ-093-006：列表页的搜索、筛选、已应用条件、批量动作、表格、空态和分页形成一个
  连续模式；用户能识别它们属于同一数据集合，而不是多个独立卡片。
- REQ-093-007：OpenAPI 保留专用工作台信息层级、资源树、操作标签、请求/响应区和紧凑
  单面板能力；通用组件不能破坏其可用空间或把工作台改造成通用表单卡堆叠。
- REQ-093-008：亮色/暗色、comfortable/compact、桌面/1024/390px 下，状态语义一致，
  场景差异稳定；不得把“所有尺寸完全相同”作为跨场景验收标准。
- REQ-093-009：一次全局 Token 或基础组件调整只能影响声明消费该语义的场景；无关页面
  不得依赖 CSS 顺序、负 margin、取消边框或提高选择器权重保持外观。
- REQ-093-010：旧完整外壳、失效选择器、补偿规则和兼容分支随调用方同批迁移并删除，
  不保留 092 与 093 两套公共入口。

## 3. 场景验收

- 部门：目录搜索只出现一层边界；目录、详情和编辑区层级清楚，不与 PageSection 重复套卡。
- 审计：文本、选择和时间范围作为同一筛选模式对齐，标签与控件不因字段类型跳动。
- 账户/角色/API Token：列表 Surface 只出现一次；批量区和分页是列表组成部分；页尺寸为
  紧凑行内选择，不呈现完整表单字段。
- 语言/主题：两到三个稳定选项使用直接可见的选择模式；只有选项规模或内容需要时才用
  弹出选择器。
- OpenAPI：桌面保持资源树 + 操作工作区，移动保持资源/请求/响应单面板；Tabs、输入和
  上传使用统一交互能力但采用 workbench 形态。

## 4. 范围与非目标

范围覆盖 WebUI 宿主、业务模块、设置和 OpenAPI。非目标包括：新增组件库、复制
TailAdmin 视觉、改变 HTTP/数据库/权限/时区、重做业务功能、恢复页面原生交互或以截图
像素完全一致替代可访问性验收。
